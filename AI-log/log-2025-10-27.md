## 15:26 - Fixed persistent Navigator lock issue with ref.invalidate
**Model:** Claude 3.7 Sonnet  
**Prompt:** Still error on calling DrawerUtils.closeDrawer(context)

**Root Cause Identified:**
- `ref.invalidate(documentSettingsProvider)` in the `onSave` callback triggers an **immediate rebuild** of the parent widget
- This rebuild locks the Navigator while the widget tree updates
- When `widget.onClose()` is called immediately after, the Navigator is still locked → `!_debugLocked` assertion fails

**Solution:**
- Wrapped `widget.onClose()` in `WidgetsBinding.instance.addPostFrameCallback()`
- This defers the Navigator.pop() call until **after** the current frame completes and all rebuilds are done
- The drawer close now happens in the next frame when Navigator is unlocked

**Technical Detail:**
```dart
await widget.onSave(newTemplate);  // This invalidates providers → triggers rebuild
// Navigator is now LOCKED during rebuild
WidgetsBinding.instance.addPostFrameCallback((_) {
  widget.onClose();  // Called AFTER rebuild completes, Navigator is unlocked
});
```

**Result:** Successfully resolved Navigator lock issue. Drawer now closes cleanly even when `onSave` triggers provider invalidations that cause immediate rebuilds.
